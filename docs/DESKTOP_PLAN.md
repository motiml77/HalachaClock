> **סטטוס: תכנון בלבד. לא נכתבה שורת קוד דסקטופ אחת בעץ העבודה.**
> אבל התוכנית **לא תיאורטית**: הפיצול למודול משותף בוצע מקצה לקצה על עותק
> חד-פעמי של הריפו והבילד עבר; MSI לדוגמה נבנה ונמדד; ועברית ב-RTL רונדרה

### 1.4 ✅ פרטי בנייה שנבדקו — ולא לנחש אותם מחדש

**אסור `kotlin { jvmToolchain(17) }`.** הוא נכשל על המכונה הזו: Gradle 8.14.2
לא מאתר את ה-JDK 17 המותקן ב-`C:\Program Files\Microsoft\jdk-17.0.19.10-hotspot`
ומודיע `Toolchain download repositories have not been configured`. הנוסח שעובד:

```kotlin

plugins { alias(libs.plugins.kotlin.jvm) }

kotlin { compilerOptions { jvmTarget.set(JvmTarget.JVM_17) } }

    sourceCompatibility = JavaVersion.VERSION_17
    targetCompatibility = JavaVersion.VERSION_17
}
dependencies {
    api(libs.kosherjava.zmanim)   // api ולא implementation — ראה למטה
    api(libs.javax.inject)
    testImplementation(libs.junit)

```

- **`api` ולא `implementation` ל-KosherJava** — הטיפוסים דולפים דרך החתימות

- ✅ **Hilt עובד מעל מודול JVM לא-אנדרואידי** — לא הנחה: Dagger ייצר בפועל
  `MaranZmanimEngine_Factory.java` תחת `:app`. אין צורך לפרק את האנוטציות.
- ✅ **desugaring לא צריך שינוי** — `assembleRelease` עבר עם ההגדרות הקיימות.
- אפשר למחוק את `implementation(libs.kosherjava.zmanim)` מ-`app/build.gradle.kts`
  אחרי המעבר — הוא נעשה מיותר.

## 2. הטכנולוגיה: Compose Multiplatform Desktop

**ההכרעה: Compose Desktop (JVM).** הטיעון אינו "נוח" אלא **בלעדי**: המנוע
קשור ל-KosherJava (בייטקוד ג'אווה) ול-`java.time`, ואין לו מסלול קומפילציה
ל-Kotlin/JS או Wasm. Kotlin Multiplatform לא פותר את זה — `commonMain` אוסר
במפורש שימוש ב-API של ה-JDK.

- **Electron / Tauri** = כתיבה מחדש על `KosherZmanim`, שה-README שלה אומר
  `This project is at an alpha stage` ו-`not all methods have been tested for accuracy`.
  המשפט השני הוא המכריע ללוח זמנים.
- **.NET / WPF** = `Yitzchok/Zmanim` — commit אחרון 2023-08, release אחרון 2021.
- **KosherKotlin** (פורט KMP) = ארכיטקטורה מחדש, לא drop-in. 64 הבדיקות
  מאמתות את המנוע מול `com.kosherjava:zmanim:2.5.0` ספציפית; החלפת המצע
  בצד אחד מבטלת אותן בשקט.

✅ KosherJava 2.5.0 נבדק בתוך ה-JAR: אפס תלויות ריצה, בייטקוד Java 8, אפס
אזכורי android, ועדיין הגרסה האחרונה באוגוסט 2026.

### 2.3 מנוע רינדור — הגדרת מילוט חובה

Skiko משתמשת ב-DirectX כברירת מחדל ב-Windows. שרשרת הנפילה אומתה בקוד המקור:
`ANGLE → DIRECT3D → OPENGL → SOFTWARE_FAST → SOFTWARE_COMPAT`.
היו קריסות היסטוריות בחלון שקוף (skiko#327, CMP#3171, CMP#3757, CMP-7404
— NVIDIA מרנדרת חלון שקוף כשחור).

לחשוף בהגדרות את `skiko.renderApi`, ולדעת שקיימת מיתוג נוסף:
`skiko.rendering.angle.enabled=true` (דורש את הארטיפקט `skiko-awt-runtime-angle`).
זו **הגדרה נדרשת, לא רשות.**

## 3. התזכורות הקופצות

הדרישה: "רק תזכורות שקופצות על המסך אם משתמש בוחר" — **בלי קול**.

### 3.1 הממצא שקובע הכול

`java.awt.TrayIcon.displayMessage` — וגם `TrayState.sendNotification` של
Compose, שיושבת עליו — **לא יכולה להיות שקטה**. השרשרת נעקבה מקצה לקצה בקוד
המקור: `sendNotification` → `Tray.desktop.kt` → `TrayIcon.MessageType` →
`awt_TrayIcon.cpp` → `Shell_NotifyIcon` עם `dwInfoFlags` שהוא אחד מ-
`NIIF_ERROR/WARNING/INFO/NONE` בלבד. **`NIIF_NOSOUND` לא מופיע בקובץ כלל.**
`NIIF_NONE` = "בלי אייקון", לא "בלי קול". אין תפר שאפשר להזריק בו דגל השתקה.

בנוסף המסלול מתפורר: adoptium-support#987 "Windows 11: Notifications vanishes
after few seconds" פתוח מ-2024-01-05, משוחזר על Java 21.0.1, בלי תגובת מתחזק.

### 3.2 המסלול הנבחר

**Toast אמיתי של Windows דרך עוזר נייטיב.** אפליקציית JVM לא-ארוזה *כן*
יכולה — אין צורך ב-MSIX — בתנאי שיש **AppUserModelID רשום**.

```
snoretoast.exe -appID com.zmanimclock.HalachClock -t "עלות השחר" -m "04:37" -silent -d short
```

**SnoreToast v0.9.1** (2025-10-27), LGPL-3.0. ⚠️ תיקון: המקור הקנוני הוא
`download.kde.org/stable/snoretoast/` ו-`invent.kde.org` — **לא** v0.7.0 שמופיע
במראה ב-GitHub. הפעלה כתהליך נפרד ב-`ProcessBuilder` = בלי linking = ה-LGPL
לא מדביקה, אבל צריך לצרף את טקסט הרישיון ולאפשר למשתמש להחליף את הבינארי.

### 3.3 ⚠️ שני חורים שהיו בגרסה הקודמת של המסמך

**א. `jpackage` לא יכול לרשום AUMID.** רשימת האפשרויות המלאה שלו היא
`--win-console, --win-dir-chooser, --win-help-url, --win-menu, --win-menu-group,
--win-per-user-install, --win-shortcut, --win-shortcut-prompt, --win-update-url,
--win-upgrade-uuid`. **אין אפשרות להציב `System.AppUserModel.ID`** על קיצור הדרך.
כלומר `--win-menu` לבדו **לא** מספק את מסלול A. הרישום חייב להיעשות ע"י משהו
אחר — `snoretoast.exe --install "HalachClock\HalachClock.lnk" "<exe>" "<appID>"`
כשלב אחרי ההתקנה, או כתיבת קיצור הדרך ב-WiX.

**ב. `-appID` לא רושם כלום.** משמעותו "השתמש במזהה הזה **במקום** ליצור קיצור
דרך". העברת `-appID` עם מזהה שמעולם לא נרשם היא **בדיוק** תרחיש הבליעה השקטה.
הרישום קודם, השימוש אחר כך.

**ג. תיקון:** מסלול הרג'יסטרי מתועד ע"י מיקרוסופט תחת **HKLM** בלבד
(`HKLM\Software\Classes\AppUserModelId\<AUMID>`), מה שדורש הרשאות מנהל. כתבתי
קודם "HKLM או HKCU" — ה-HKCU הוא ידע קהילתי, לא תיעוד. **להעדיף את מסלול
קיצור הדרך**, שהוא גם מה שמיקרוסופט ממליצה עליו במפורש.

### 3.4 שקט — ארבעה תרחישים אסורים, לא שניים

**אסור** `scenario="reminder"` למרות שם הפיצ'ר. תיקון: יש **ארבעה** תרחישים
שכופים או מלפפים שמע — `reminder`, `alarm`, `incomingCall`, `urgent`. הקוד
צריך לאסור את כולם, עם הערה שמסבירה למה, אחרת מישהו "יתקן" את זה בעתיד.
הקונפיגורציה הנכונה היחידה: scenario ברירת מחדל + `<audio silent="true"/>`
(או `-silent`).

### 3.5 ✅ עברית עוברת ל-toast בשלום

נבדק במקור, לא הונח: ה-JDK בונה את שורת הפקודה כ-UTF-16 וקורא ל-`CreateProcessW`
עם ה-`jchar*` של המחרוזת, בלי המרת קידוד; SnoreToast נכנס ב-`wWinMain` ומפרסר
דרך `GetCommandLineW` + `CommandLineToArgvW` ל-`std::wstring`. שני הקצוות
UTF-16 — אין שלב תעתוק שיכול לשבש עברית.

⚠️ **זה לא נכון תחת GraalVM native-image** — שם argv לא-ASCII הופך ל-U+FFFD.
לא להריץ native-image על המשגר בלי בדיקה חוזרת.

### 3.6 תזמון — שעון קיר, לא השהיה

**אסור** `ScheduledExecutorService.schedule(delay)` עד שעת הזמן.
`ScheduledThreadPoolExecutor` מחשב דדליינים מ-`System.nanoTime()`, שב-Windows
לא מתקדם דרך suspend: אחרי שינה של 600 שניות, השהיה של 60 שניות נורית ב-660.

במקום זה: tick של 15–30 שניות שמשווה `Instant.now()` לטבלת הזמנים. האפליקציה
ממילא רזידנטית בשביל הווידג'ט, אז אין עלות נוספת. חישוב מחדש ב: הפעלה, מעבר
תאריך, יציאה משינה, שינוי אזור זמן, שינוי מיקום. דגל "נורה" פר-(תאריך, זמן)
נשמר לדיסק, כדי שהפעלה מחדש לא תדליק תזכורת פעמיים.

**אין Task Scheduler** — הוא מוסיף שטח התקנה והרשאות ולא קונה כלום כשהאפליקציה
רזידנטית ממילא.

### 3.7 אחרי שינה — מעתיקים את Windows עצמה

חלון מסירה של **5 דקות**, מילה במילה כמו ה-semantics של
`ScheduledToastNotification`: *"If the computer is turned off during the
scheduled delivery time, and remains off for longer than 5 minutes, the
notification will be dropped as no longer relevant."*
עבר פחות מ-5 דקות ⟶ מציגים; יותר ⟶ מסמנים "הוחמץ". **לעולם לא מנגנים תור.**

**אין `WakeToRun`** — להעיר מחשב ישן סותר את "זו לא שעון מעורר".

### 3.8 ⚠️ כנות בממשק — כולל "נא לא להפריע"

הניסוח שכתבתי קודם היה חסר. Do Not Disturb / Focus **נדלק אוטומטית**
כברירת מחדל בשכפול מסך, במשחק ובאפליקציה במסך מלא, ואז הוא בולע באנרים
**וגם** צלילים ומנתב למרכז ההתראות בשקט. הניסוח הנכון:

> תזכורת תופיע רק אם המחשב פעיל ומצב "נא לא להפריע" כבוי.

### 3.9 סדר ה-spike — להיכשל מהר

בליעה שקטה בלי שגיאה היא תרחיש הכישלון הצפוי, אז **אין לדבג את צד ה-Kotlin

## 4. הווידג'ט על שולחן העבודה

### 4.1 מה זה לא: לוח הווידג'טים של Windows 11

נדחה על **ארבעה** יסודות מבניים:

1. הוא **חלונית מתפרצת** שנפתחת ב-Win+W ומכסה את שולחן העבודה — לא שולחן
   העבודה עצמו. אין API להניח ווידג'ט על הרקע.
2. רק אפליקציות **ארוזות ב-MSIX** יכולות להירשם כספק ווידג'טים.
3. הספק חייב להיות **שרת COM חוץ-תהליכי ב-WinRT** שמממש `IWidgetProvider` —
   C#/C++/Rust בלבד. **אין הטלת WinRT ל-JVM.**
4. ✅ `jpackage` לא מייצר MSIX כלל — נבדק היום מקומית:
   `--type` מקבל `{"app-image", "exe", "msi"}` בלבד.

⚠️ שני תיקונים לנימוקים ששמעתי ואינם מחזיקים: הטענה ש"הפלטפורמה קפואה"
**לא נכונה** — ה-API דווקא גדל דרך Windows App SDK 2.0 והתיעוד רוענן ב-07/2026.
והטענה "Adaptive Cards בלבד" **מיושנת** — יש עכשיו web widgets מעל WebView2.
אבל זה עושה את המסלול **גרוע יותר**, לא טוב יותר: עדיין צריך עטיפת Adaptive
Card, עדיין MSIX + COM, ועכשיו **גם נקודת קצה HTTPS ציבורית** — לאפליקציית
זמנים שאמורה לעבוד לגמרי אופליין.

### 4.2 מה זה כן — שני מצבים, והמשתמש בוחר

| מצב | מנגנון | סיכון | מתי |
|---|---|---|---|
| **א. צף מעל הכול** (ברירת מחדל) | `alwaysOnTop = true` — פרמטר מובנה | **אפס** | רוצים לראות תמיד |
| **ב. נעוץ בשולחן העבודה** | JNA: `WS_EX_TOOLWINDOW` + `WS_EX_NOACTIVATE` + `SetWindowPos(HWND_BOTTOM)` | בינוני, שטח לא-מתועד | רוצים שייעלם מאחורי חלונות |

```kotlin
Window(
    undecorated = true,      // בלי מסגרת
    transparent = true,      // מחייב undecorated
    alwaysOnTop = mode == FLOATING,
    resizable = true,
) { WindowDraggableArea { … } }
```

כל תכונה כאן היא פרמטר מובנה של `Window` — אומת מול המקור עצמו.

**החלטה הנדסית למצב ב':**
- ✅ **לא** `SetParent` ל-WorkerW. ex-styles + `HWND_BOTTOM` הם המנגנון המתועד
  ואינם תלויים בהיררכיית ה-shell. נבדק על המכונה הזו (Windows 11 25H2,
  build 26200): `SHELLDLL_DefView` הוא **ילד ישיר של Progman**, ומתוך 18 חלונות
  `WorkerW` עליונים **אף אחד לא מאחסן אותו** — המתכון הקלאסי כבר לא תקף.
- **טיימר סקירה, לא subclassing.** החזרת `HWND_BOTTOM` על `WM_WINDOWPOSCHANGED`
  דורשת `SetWindowLongPtr(GWLP_WNDPROC)` עם `JNA Callback` — ניהול חיי callback
  מול ה-GC, זיקת thread ל-AWT event thread, ושרשור `CallWindowProc` נכון. טעות
  שם **מפילה את ה-JVM**, לא מדרדרת. סקירה תקופתית היא הברירה הבטוחה.
- **Win+D יעלים את הווידג'ט.** אין API נתמך למנוע זאת. המצב הזה כבוי כברירת
  מחדל, וכל כשל מדרדר ל"נעלם עד שלוחצים שוב על שולחן העבודה". Rainmeter 4.5.26
  (2026-05-20) היא מימוש ייחוס פתוח שמטפל בזה, כולל שער גרסה על
  `GetCurrentMonitorTopologyId` (build 10.0.26100.2454).
- **לבודד את שכבת הנעיצה מאחורי ממשק קטן** — כשעדכון פיצ'ר של Windows יזיז
  משהו, ישתנה קובץ אחד ומנוע הזמנים לא ייגע.

### 4.3 ⚠️ החלטה ארכיטקטונית שחייבת להיקבע מראש: שני חלונות

`focusable = false` יחד עם `WS_EX_NOACTIVATE` פירושו שהווידג'ט **לעולם לא
יקבל קלט מקלדת**. עכבר כן — כפתורים וגרירה עובדים. אבל כל הקלדת טקסט (חיפוש
עיר, היסטים, הגדרות) חייבת לחיות ב**חלון רגיל ונפרד** שנפתח מהטריי או מלחיצה
על הווידג'ט.

**זה לא פרט מימוש — זה עיצוב עץ ה-composable.** רטרואקטיבית זה ארכיטקטורה
מחדש. נקבע בשלב 2, לא בשלב 4.

בונוס: כך גם התנהגות ה-IME והפריסה העברית מתורגלת רק בחלון ההוא.

### 4.4 מגבלה קשיחה: כרטיס אטום

באזורים שקופים **הקלקות לא עוברות דרך** החלון. ⚠️ תיקון להערכה קודמת: זה לא
"דיווח מ-2021" — JetBrains סגרה את CMP-6036 בתאריך 2025-12-15 בסטטוס
**Obsolete**, כלומר נסגר בלי לספק את ההתנהגות. זו מגבלה קבועה.

לכן הווידג'ט הוא **כרטיס אטום עם פינות מעוגלות**, לא צורה לא-רגולרית עם שטח
שקוף גדול.

הערה נוספת: `WS_EX_TRANSPARENT` לבדו **אינו** נותן click-through — הוא סגנון
סדר-ציור. ההתנהגות מגיעה רק מהצירוף `WS_EX_LAYERED + WS_EX_TRANSPARENT`.

### 4.6 DPI ומיקום

✅ תיקון לעצה נפוצה ומיושנת: **אין צורך לתקן את המניפסט ב-`mt.exe`.** נבנתה

אבל **מודעות ל-DPI אינה נכונות ב-DPI**: Swing/AWT טיפלו היסטורית רק ב-

`WM_DISPLAYCHANGE` ובכל הפעלה.

עברית אינה CJK ולא מצאתי דיווח עברי, אז זה **סיכון לבדוק, לא פגם מאושר** —

## 5. התקנה מלאה על המחשב

### 5.1 ✅ הגודל נמדד — לא מוערך

כתבתי קודם "60–90MB, הערכה". נבנה MSI אמיתי: **60,846,016 בתים (58MB)**.
זה הגודל, בגלל ה-JRE הארוז. לא צריך יותר לנחש.

✅ ממצא נלווה לטובה: **הפלאגין של Compose מוריד את WiX לבד** (`:downloadWix` →
`:unzipWix` → `:packageMsi`). זה עבד על מכונה בלי WiX מותקן. אבל המשמעות היא
ש**בילד הפצה דורש גישת רשת ל-github.com** — ייכשל ברשת סגורה.

### 5.2 שני מסלולי אריזה — וההמלצה השתנתה

| | **MSI** (jpackage/Compose) | **MSIX** (Conveyor) |
|---|---|---|
| נוצר ע"י | הפלאגין, מובנה | Conveyor, כלי חיצוני |
| חתימה | ידנית ב-`signtool` | מכל פלטפורמה, מובנה |
| עלות חתימה לישראלי יחיד | ~$150–300/שנה + טוקן חומרה | **חינם** דרך החנות |
| עלייה אוטומטית | מפתח רג'יסטרי בכתיבה עצמית | `app.windows.start-on-login` מובנה |
| עדכון אוטומטי | — | מובנה |
| SmartScreen | אזהרה עד שנצבר מוניטין | **בלי אזהרות** אם דרך החנות |

**התיקון המשמעותי ביותר במסמך הזה:** כתבתי קודם שהחתימה היא "הפריט הכי ארוך"
ושהאפשרויות הן OV בתשלום או Conveyor. **פספסתי שני מסלולים חינמיים
עולמיים** שמיקרוסופט עצמה מפרטת:

1. **Microsoft Store MSIX** — עלות **חינם**, זמינות **עולמית**, SmartScreen
   **בלי אזהרות**, כי *"Microsoft re-signs your package after certification
   and you don't need to purchase or manage a certificate."* המגבלה
   הגיאוגרפית על ישראל **נעלמת לגמרי**.
2. **SignPath Foundation** — חתימה ברמת OV בחינם לפרויקטי קוד פתוח כשירים.

### 5.3 קונפיגורציית MSI (אם נשארים במסלול הזה)

```kotlin
compose.desktop {
    application {
        mainClass = "com.zmanimclock.desktop.MainKt"
        nativeDistributions {
            targetFormats(TargetFormat.Msi)
            packageName = "HalachClock"          // ASCII — שם המוצר בעברית ב-UI
            packageVersion = "1.0.0"
            modules("java.desktop", "java.naming")  // חובה — ראה למטה
            windows {
                menuGroup = "שעון זמנים"
                perUserInstall = true            // בלי הרשאות מנהל
                dirChooser = true                // המשתמש בוחר תיקייה
                shortcut = true
                iconFile.set(project.file("icon.ico"))
                upgradeUuid = "<GUID קבוע לנצח>"  // בלעדיו כל שדרוג = התקנה כפולה
            }
        }
    }
}
```

שתי מלכודות מתועדות:
1. **אין cross-compilation.** MSI/EXE נבנים רק על Windows; משימות לא-תואמות
   מדולגות **בשקט**.
2. **jlink לא מזהה מודולים לבד** — מודול חסר = `ClassNotFoundException` בזמן
   ריצה, לא בזמן בילד. המנוע נוגע רק ב-`java.base`, אבל הטריי גורר
   `java.desktop`. `suggestModules` עוזר, אבל "הפלט עשוי להיות חלקי". **בדיקת
   עשן על המותקן, לא על `run`.**

### 5.4 עלייה אוטומטית עם המחשב

זה מה שהמשתמש ביקש במפורש, אז שני המסלולים מפורטים במלואם.

#### מסלול MSIX (מועדף — נקי יותר)

```
app.windows.start-on-login = true
```

מגובה ב-**WinRT `StartupTask` API**. ⚠️ הסתייגות מהותית: `StartupTask` **דורש
package identity**, כלומר הוא זמין רק בפלט MSIX — לא ב-EXE חשוף. היתרונות:
המשתמש רואה ומנהל את זה ב-Task Manager כמו כל תוכנה אחרת, אין נגיעה ברג'יסטרי,
ואין דמיון לדפוס נוזקה.

#### מסלול MSI (מפתח רג'יסטרי)

```
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
    ZmanimClock = "C:\...\HalachClock.exe" --tray
```

- **HKCU ולא HKLM** — פר-משתמש, בלי הרשאות מנהל, מתיישר עם `perUserInstall`.
- **opt-in, לא ברירת מחדל**, עם תיבת סימון גלויה בהגדרות שכותבת/מוחקת את הערך
  בזמן אמת. כיבוי = מחיקת הערך, לא "נטרול".
- דגל `--tray` = עולה מוסתר לטריי, בלי לקפוץ חלון בכל בוט.
- Windows עשויה להשהות אפליקציות Run-key בהפעלה. לזמנים זה בסדר; לשעון מעורר
  זה לא היה מתקבל — עוד סיבה שהתוכנה הזו אינה שעון מעורר.
- **Fast Startup** של Windows הופך "כיבוי" ל-hibernate היברידי. לוודא שהטריי
  עולה מחדש, מחשב זמנים מחדש, ושתזכורת ישנה מהסשן הקודם לא נורית.

⚠️ **אזהרה שצריכה להיאמר:** כתיבת מפתח Run היא דפוס התמדה מוכר של נוזקות
(MITRE ATT&CK T1547.001). אפליקציה **לא חתומה** שרושמת את עצמה לעלייה
אוטומטית היא התאמה היוריסטית לאדוור. Smart App Control ב-Windows 11 חוסם
בינאריים לא חתומים **גם אם לא הורדו מהאינטרנט**, וחתימה עצמית מתנהגת בדיוק
כמו חוסר חתימה.

**זו הסיבה האמיתית להעדיף את מסלול MSIX/חנות: הוא פותר את החתימה, מחליף את
מפתח הרג'יסטרי ב-API מתועד, ומבטל את חשד ה-AV — שלושתם במכה אחת.**

### 5.5 אחסון נתונים

באנדרואיד יש Room + DataStore. בדסקטופ **אין צורך במסד נתונים** — אין שעונים
לשמור. הצימוד ל-DataStore הוא קובץ אחד בלבד (`UserPreferencesRepository.kt`).

```
%LOCALAPPDATA%\HalachClock\
├── settings.json        עיר, זמנים לתזכורת, סינון "הזמן הבא", autostart
├── widget.json          מצב (צף/נעוץ), מזהה מסך + היסט, גודל, שקיפות, זמנים
├── chai_cache.json      הנץ נראה שהורד
└── fired.json           דגלי "נורה" פר-(תאריך, זמן)
```

### 5.6 מה מפורשות **לא** עובר

Room · WorkManager · DataStore · Hilt (די בבנייה ידנית — `MaranZmanimEngine()`
עובד ללא ארגומנטים) · `BootReceiver` · `AlarmManager` · `AlarmSoundService` ·
`AlarmActivity` · `LoudnessEnhancer` · נודניק · תרגיל חשבון · רטט · רינגטונים ·
`OemHelper` · הרשאות ריצה.

**כן עובר** (בניגוד לנטייה הראשונית): OkHttp · jsoup · ChaiTablesFetcher —
ראה 1.7.

## 7. סיכונים — מה נסגר ומה עדיין פתוח

### ✅ נסגר מאז הגרסה הקודמת

| מה | איך |
|---|---|
| "עברית ב-Compose Desktop לא מאומתת" | רונדר ואומת ויזואלית — שיפינג, BiDi, יישור, גרשיים |
| "גודל ה-MSI הוא ניחוש" | נמדד: 60,846,016 בתים |
| "האם הפיצול בכלל יעבוד" | בוצע מקצה לקצה: 64+44 ירוקות, APK נבנה, אפס עריכות `.kt` |
| "האם Hilt יסתדר עם מודול JVM" | Dagger ייצר את ה-Factory בפועל |
| "האם צריך לתקן מניפסט DPI" | לא — PerMonitorV2 כבר שם |
| "האם WiX צריך התקנה ידנית" | לא — הפלאגין מוריד אותו |

### ⚠️ עדיין פתוח

1. **חלון חי, לא רק רינדור אופסקרין.** ההוכחה העברית היא רינדור Skia
   אופסקרין. היא מוכיחה שיפינג, BiDi ומירור — **לא** התנהגות חלון חי:
   `transparent + undecorated + alwaysOnTop` יחד על שולחן עבודה אמיתי,
   ריבוי מסכים, DPI, והתנהגות מעל אפליקציות מסך-מלא. **spike חובה.**
2. **עברית ב-toast של Windows.** ההעברה מה-JVM לעוזר בטוחה (3.5), אבל איך
   ה-shell מרנדר "עלות השחר 4:37" ב-locale עברי מול אנגלי — לא מתועד בשום
   מקום. ייתכן שיידרשו סימני RLM/LRM. **ביטחון נמוך.**
3. **COM activator.** לא הוכרע אם `INotificationActivationCallback` נדרש
   כדי *להציג*. עצם קיומו של SnoreToast (שמשתמש ב-named pipe ולא ב-activator)
   הוא ראיה נסיבתית חזקה שלא — אבל לא תיעוד. עיצוב "תצוגה בלבד" ב-v1 עוקף.
4. **Compose ומול ex-styles חיצוניים.** Compose לא מצפה שגורם שלישי ישכתב
   את ה-ex-styles של החלון שלה מתחתיה. מסירת אירועי עכבר למשטח Skia
   לא-מפעיל בתחתית ה-z-order היא הדבר הספציפי לאמת ב-spike.
5. **HKCU ל-AUMID** — ידע קהילתי, לא תיעוד. מיקרוסופט מתעדת HKLM בלבד.
6. **ריבוי מסכים ו-DPI שברי** — JBR מעגלת קנה-מידה שברי לשלם.
7. **מפתחות באגים של OpenJDK** (JDK-8146527 וחבריו) — `bugs.openjdk.org`
   מחזיר 403 לאוטומציה, אז הם מקור משני. הארכיטקטורה (tick שעון-קיר) נכונה
   בכל הווריאנטים, אבל לא לצטט אותם כמאומתים בלי בדיקה מדפדפן.
8. **כשירות Azure Artifact Signing** — כללי הזכאות משתנים; לאמת לפני תקצוב.
9. **צימוד Kotlin/Compose** — נעילה על Compose MP 1.10.0 קונה תאימות היום
   אבל משאירה את הדסקטופ גרסה אחת מאחור. הפיצ'ר הבא עלול לכפות מעבר ל-Kotlin
   2.2.x, שגורר AGP + KSP + Hilt יחד — שינוי אמיתי באפליקציה שכבר בשטח.
10. **תחום לא-מתועד מעצם טבעו.** מיקרוסופט תומכת ב-API אחד בלבד לנדל"ן קבוע
    על שולחן העבודה (appbars, עגינה לקצה). כל השאר מורכב מפרימיטיבים מתועדים
    בצירוף שמיקרוסופט מעולם לא בירכה עליו — ולכן Rainmeter נאלצה לשכתב את
    הקוד הזה לאחרונה. **לצפות לחזור לשכבת הנעיצה בכל עדכון פיצ'ר של Windows.**

## 8. שאלות פתוחות למשתמש

1. **MSI או חנות Microsoft?** מסלול החנות נותן חתימה חינם, בלי אזהרת
   SmartScreen, ועלייה אוטומטית דרך API מתועד במקום רג'יסטרי — אבל מחייב
   חשבון מפתח, אישור החנות, ורישום ציבורי של האפליקציה. MSI זה קובץ שמעבירים
   ביד, בלי אישורים — אבל עם אזהרה בהתקנה עד שנצבר מוניטין.
2. **הווידג'ט — צף מעל הכול, או נעוץ בשולחן העבודה?** אפשר לספק את שניהם
   כהגדרה (4.2). המצב הצף הוא אפס-סיכון; הנעוץ נכנס לשטח לא-מתועד ונעלם
   ב-Win+D. ברירת המחדל המוצעת: **צף**.
3. **אילו זמנים ברירת מחדל לתזכורת?** ההצעה: להתחיל **בלי אף תזכורת** —
   הכול opt-in — ושהמשתמש יבחר.
4. **תזכורת כשהתוכנה סגורה לגמרי** — נדרש? כרגע התכנון הוא "רק כשרצה"
   (טריי + autostart מכסים בפועל). אם כן — זה דורש `AddToSchedule` שלא אומת
   מ-JVM, ומחקר נפרד.
5. **גרסה ניידת (portable, בלי התקנה)** — נדרשת? אם כן, צריך להחליט עכשיו אם
   האפליקציה רושמת AUMID בעצמה בהרצה ראשונה, אחרת לא יהיו לה toasts כלל.
